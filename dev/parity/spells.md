# Hardcoded PST spells: EE engine vs GemRB

Generated by `tools/parity/gen_docs.py`. PST hardcodes 36 spells as projectile classes (`CPsSpell*` in the
PST:EE Linux binary, which keeps its symbols; the original exe builds the same objects in `sub_559A5D`). The
SPL file only carries part of the spell: the class picks targets, rolls, applies extra effects and plays
its own animations and sounds. GemRB approximates each with a `.pro` in `gemrb/unhardcoded/pst` plus
helper SPLs named by the projectile's GemRB-only `failureSpell`/`successSpell` fields.

- **Code ops**: effects the EE class creates in code (not in the SPL). Each must have a GemRB equivalent.
- **Logic**: what the class does besides playing visuals.
- **GemRB helpers**: helper SPLs the GemRB projectile casts, with their opcodes.
- **Assets only EE uses**: animations/sounds the class plays that no GemRB file references.
- **Suite**: last `tb_spell_suite.py` result.
